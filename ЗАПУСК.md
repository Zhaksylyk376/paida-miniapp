# Paida — как запустить новую версию

Приложение переделано на **облако WeChat (云开发 / CloudBase)**. Теперь заказы и
водители хранятся на сервере, поэтому клиент и водитель видят друг друга —
как и должно быть. Ниже — пошагово, что сделать в WeChat DevTools. Один раз.

---

## Что изменилось (коротко)

- Раньше всё хранилось на одном телефоне (`wx.getStorageSync`) — это была витрина без сервера.
- Теперь всё идёт через одну облачную функцию **`paida`** (папка `cloudfunctions/paida`).
- Вход — по WeChat-аккаунту (openid), подделать нельзя.
- Флоу: **клиент создаёт заказ → водители откликаются → клиент выбирает одного → KYC клиента → договор → статусы рейса**.
- Регистрация водителя: загрузка **техпаспорта, прав и фото машины** + автопроверки + ручное одобрение админом.
- **KYC клиента** (новое): 身份证 / 营业执照 (КНР) или ИИН / БИН (КЗ) + фото документа. Гейт перед подписанием договора.
- **Договор с криптоподписью** (новое): SHA-256 fingerprint от snapshot договора + серверный timestamp + openid обеих сторон.
- **Арбитражная оговорка + стандартные пункты** (новое): CIETAC / AIFC IAC, простой, таможенная задержка, повреждение груза.
- **Пункты пропуска и ETA** (новое): выбор границы (Хоргос / Алашанькоу / Бахты / Торугарт / Иркештам), карта с маркером, оценка расстояния и итогового ETA с учётом очереди на таможне.

---

## Шаг 1. Включить облако

1. Открой проект в WeChat DevTools.
2. Сверху нажми **«云开发» (Cloud)**. Если попросит — согласись создать окружение (环境).
3. Дай окружению имя (например `paida-prod`). После создания скопируй **env ID**
   (в консоли облака: 设置 / Settings → «环境 ID»). Выглядит примерно так: `paida-prod-1abc234de`.

## Шаг 2. Вписать env ID в код

Открой файл **`app.js`**, найди строку:

```js
cloudEnv: 'REPLACE_WITH_YOUR_ENV_ID',
```

и вставь свой env ID:

```js
cloudEnv: 'paida-prod-1abc234de',
```

Сохрани.

## Шаг 3. Создать коллекции в базе

В консоли облака → **数据库 (Database)** создай **4 коллекции** (кнопка «+»):

| Коллекция       | Что хранит                          |
|-----------------|-------------------------------------|
| `users`         | пользователи и их роль              |
| `drivers`       | анкеты водителей + документы        |
| `orders`        | заказы клиентов                     |
| `applications`  | отклики водителей на заказы         |

Права доступа для каждой коллекции поставь **«仅创建者可读写» / только через облачные функции**
(рекомендуется «Только облачные функции могут читать и писать»). Это важно для
безопасности — тогда напрямую из телефона в базу залезть нельзя, только через нашу функцию.

## Шаг 4. Задеплоить облачную функцию

1. В дереве файлов слева раскрой папку **`cloudfunctions`**.
2. Правый клик по папке **`paida`** → **«上传并部署：云端安装依赖»**
   (Загрузить и задеплоить: установить зависимости в облаке).
3. Подожди, пока внизу не появится «上传成功» (успешно).

> Если правого клика с этим пунктом нет — убедись, что в `project.config.json` есть
> строка `"cloudfunctionRoot": "cloudfunctions/"` (она уже добавлена).

## Шаг 5. Хранилище для документов

Ничего настраивать не нужно — облачное хранилище (存储) включается вместе с облаком.
Фото документов грузятся в папку `driver-docs/`. При желании в консоли облака →
**存储 (Storage)** можно посмотреть загруженные файлы.

## Шаг 6. Назначить себя админом

Админ — это тот, кто одобряет водителей. Чтобы стать админом:

1. Запусти приложение в симуляторе.
2. Открой **вкладку «Отладка» → Console** и выполни (или временно добавь кнопку),
   либо проще: зайди в приложение, оно само вызовет `login`. Затем в консоли облака →
   数据库 → коллекция `users` найди свою запись и скопируй значение поля **`_openid`**.

   > Быстрый способ узнать свой openid: в консоли облака → 云函数 (Functions) → `paida` →
   > «云端测试 / Test», в теле запроса впиши `{ "action": "whoami" }` и запусти —
   > вернётся твой `openid`.

3. Открой **`cloudfunctions/paida/index.js`**, найди вверху:

   ```js
   const ADMINS = [
     // 'oXXXXXXXXXXXXXXXXXXXXXXXXXXX'
   ]
   ```

   и впиши туда свой openid:

   ```js
   const ADMINS = [
     'oABC123...твой_openid...'
   ]
   ```

4. Снова задеплой функцию `paida` (как в шаге 4).

Теперь на главной у тебя появится карточка **«Панель проверки»** — там ты одобряешь
или отклоняешь водителей.

## Шаг 7. Карты (пункты пропуска)

Ничего настраивать не нужно — используется встроенный компонент `<map>` WeChat.
Координаты 5 пунктов пропуска (Хоргос, Алашанькоу, Бахты, Торугарт, Иркештам)
уже прописаны в `utils/config.js`. Клиент выбирает пункт в форме заказа —
на карте появляется маркер и разбивка ETA: расстояние + дни в пути + очередь на таможне.

> Если понадобится геокодинг или маршрутизация (сейчас не используется),
> нужно будет получить ключ Tencent Location Service в
> [lbs.qq.com](https://lbs.qq.com) и добавить его домен в whitelist mp.weixin.qq.com.

## Шаг 8. KYC клиента

Ничего настраивать не нужно — работает через ту же облачную функцию `paida`.
Клиент открывает «О Paida» → карточка «Верификация заказчика» → выбирает
страна × тип × заполняет ID + загружает фото документа.

Автопроверки на сервере:
- формат идентификатора: 身份证 (18), 营业执照 USCC (18), ИИН (12), БИН (12)
- антифрод: один и тот же ID не может числиться за двумя openid

Статус `submitted` уже разблокирует подпись договора. Для полноценной юридической
верификации позже можно добавить админ-ревью (по аналогии с водителями) или
интеграцию с внешними сервисами — 法大大 / e-签宝 (КНР), НУЦ РК.

Файлы KYC-документов ложатся в облачное хранилище в папку `client-kyc/`.

## Как проверить, что всё работает

1. **Клиент**: на вкладке «下单 / Заказ» заполни форму → выбери страну и пункт
   пропуска → на карте появится маркер границы, ниже — оценка ETA. Отправь заказ.
   Он появится в списке «Мои заказы» со счётчиком откликов.
2. **Водитель**: в «Мой профиль» (вкладка «关于») переключись на роль водителя →
   зарегистрируйся, загрузи 3 документа → анкета уйдёт «на проверку».
3. **Админ**: главная → «Панель проверки» → одобри водителя.
4. **Водитель** (после одобрения): вкладка «可接 / Доступные» → «Откликнуться» на заказ.
5. **Клиент**: «Мои заказы» → «Посмотреть и выбрать» → выбери водителя → откроется договор.
6. **Клиент нажимает «Подписать»** → если KYC не пройден, откроется страница
   верификации → заполни данные + фото документа → вернись к договору → подпиши.
7. **Водитель** подписывает договор → под каждой подписью появится SHA-256 fingerprint
   (16 символов) → водитель двигает статусы рейса.

> Чтобы проверить вдвоём (клиент и водитель как разные люди), удобно использовать
> в DevTools «真机调试 / Debug на телефоне» с двух аккаунтов, либо тестировать роли
> по очереди на одном.

## Про «проверку каждой детали» (антифрод)

Сейчас при регистрации водителя система **автоматически**:

- проверяет формат телефона и госномера;
- требует все 3 документа (без них отправить нельзя);
- **блокирует дубликаты** — если такой госномер или телефон уже зарегистрирован
  другим водителем, регистрация не пройдёт (частый признак поддельной анкеты).

Затем анкету вручную одобряет админ, глядя на фото.

**Чего пока нет** (и почему): автоматически сверить техпаспорт с госбазой (что машина
настоящая, не в угоне, права действующие) внутри мини-программы нельзя без платных
внешних сервисов проверки и доступа к государственным реестрам. В коде для этого
оставлено место: в `cloudfunctions/paida/index.js`, объект `checks`, поле
`externalVerified` — сюда позже можно подключить внешний OCR/проверку и ставить `true`
автоматически.

## Структура проекта

```
app.js                     ← инициализация облака (ВПИШИ env ID!)
utils/api.js               ← все вызовы сервера
utils/i18n.js              ← переводы ru/zh
utils/config.js            ← тарифы, страны, ПУНКТЫ ПРОПУСКА, таблицы расстояний
utils/calculator.js        ← расчёт цены + estimateRoute (км + ETA + очередь)
pages/
  index/                   ← главная (+ вход в админку)
  order/                   ← клиент: заказ + карта + мои заказы; водитель: мои рейсы
  tracking/                ← клиент: как это работает; водитель: доступные заказы
  applications/            ← клиент выбирает водителя из откликнувшихся
  contract/                ← договор с арбитражем/оговорками + SHA-256 подпись
  driver-register/         ← регистрация водителя + документы
  client-kyc/              ← верификация клиента (身份证/营业执照/ИИН/БИН)
  admin/                   ← панель проверки водителей
  about/                   ← язык, роль, профиль + карточка KYC
cloudfunctions/
  paida/                   ← весь backend (одна функция-роутер)
                             actions: whoami, login, driver*, order*,
                                      clientKyc*, contractAccept (с хэшем),
                                      orderAdvance, admin*
```

## Что внутри договора (новое, юр. часть)

`contractAccept` в облачной функции при каждой подписи делает:
1. Собирает канонический snapshot заказа (стороны + KYC клиента + предмет
   + границы + цена) в детерминированный JSON.
2. Хэширует SHA-256 → `snapshotHash`.
3. Из `[версия | snapshotHash | роль | серверное_время | openid]` считает
   `fingerprint` — тоже SHA-256. Он показывается в UI.
4. Кладёт объект подписи в `signatures[]` заказа с полями:
   `role`, `openid`, `contractVersion`, `snapshotHash`, `fingerprint`, `at`.

Изменение любого поля договора после подписи → другой fingerprint →
подмена документа технически детектируется. Готовая база под интеграцию с
法大大 / НУЦ РК (когда понадобится государственно-признанная подпись).

Текст договора двуязычный (zh/ru), содержит:
- разделы 1–4: стороны, предмет, цена, обязательства (было)
- **раздел 5**: стандартные оговорки — простой ($50/сут после 24ч),
  таможенная задержка (кто виноват — грузоотправитель/форс-мажор/перевозчик),
  повреждение груза (% от объявленной стоимости)
- **раздел 7**: арбитражная оговорка — CIETAC (китайская сторона) или
  AIFC IAC Астана (казахская сторона), исполнение по Нью-Йоркской конвенции 1958 г.
